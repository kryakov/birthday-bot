# Звёздный день

Telegram-бот на Python и aiogram 3: знаменитости с твоим днём рождения, поиск через локальную LLaMA и викторина «Угадай знак».

![Звёздный день](assets/star-day.png)

## Что умеет

- Принимает дату `ДД.ММ`, проверяет календарь, определяет знак и считает дни до рождения.
- Показывает знаменитостей по точной дате и отдельно по знаку: по три человека, с независимой пагинацией без повторов.
- Ищет по имени, псевдониму, месяцу, знаку и категории. Можно написать «блогеры моего знака», «Влад А4», «актёры в июне».
- Предлагает викторину с четырьмя вариантами и сохраняет личный счёт.
- Создаёт карточку дня рождения с кнопкой «Поделиться» и показывает сегодняшних именинников.
- Запоминает дату и счёт между запусками. Команда `/forget` удаляет их.

В каталоге 1 465 человек: минимум четыре на каждую из 366 календарных дат, включая 29 февраля. На 26 июня сохранены пять прежних записей. Есть российские и зарубежные актёры, музыканты, блогеры и спортсмены: Настя Ивлеева, Инстасамка, Влад А4, Егор Крид, MrBeast, Билли Айлиш и другие.

## Локальный запуск

Если окружение и токен уже настроены, выполни из папки проекта:

```bash
.venv/bin/python bot.py
```

Открой Telegram и отправь боту `/start`. Для остановки нажми `Ctrl+C` в терминале. Для одного токена нужен только один запущенный экземпляр.

Для AI открой приложение Ollama. В `.env` выбрана установленная модель `llama3.1:latest`. Команда `/ai` в Telegram проверяет, доступна ли модель. Компьютер, Ollama и процесс бота должны оставаться включёнными; после перехода компьютера в сон ответы могут прекратиться.

## Установка на другом компьютере

Нужны Python 3.11 или новее и доступ к Telegram. Создай бота через [BotFather](https://t.me/BotFather), сохрани токен, затем выполни из папки проекта:

```bash
python3 -m venv .venv
source .venv/bin/activate
python -m pip install -r requirements.txt
cp .env.example .env
```

На Windows PowerShell:

```powershell
py -m venv .venv
.venv\Scripts\python.exe -m pip install -r requirements.txt tzdata
Copy-Item .env.example .env
```

Не копируй `.env.example` поверх уже настроенного `.env`. Вставь токен в `.env`:

```dotenv
BOT_TOKEN=put_your_token_here
OLLAMA_BASE_URL=http://127.0.0.1:11434
OLLAMA_MODEL=llama3.1:latest
```

Токен не вставляется в исходный код. `.env`, база пользователей и локальное окружение исключены из Git и архива для передачи проекта. Переменные окружения имеют приоритет над `.env`.

Запуск с активированным окружением — `python bot.py`. На Windows без активации — `.venv\Scripts\python.exe bot.py`. Публичный сервер для локального запуска не нужен: бот использует long polling.

## Как подключена LLaMA

Установи [Ollama](https://ollama.com/download), запусти её и скачай модель, если её ещё нет:

```bash
ollama pull llama3.1:latest
```

Бот обращается к локальному адресу `http://127.0.0.1:11434/api/chat`. LLaMA переводит вопрос в JSON с фильтрами: имя, дата, месяц, знак, категория и связь с профилем. Python проверяет фильтры и выбирает реальные записи из каталога. Явно указанные дата и месяц имеют приоритет над ответом модели. Имена, даты, описания и ссылки модель не сочиняет: они берутся из JSON-файла.

Это поиск по подготовленному каталогу, а не свободный чат и не поиск по интернету. Обновление данных запускается отдельно. При недоступности модели или неверном JSON работает обычный поиск по именам и ключевым словам. На локальную модель одновременно отправляется один запрос; другой пользователь увидит предложение подождать, а меню и викторина продолжат работать.

Ответ зависит от скорости компьютера. Тайм-аут AI — 45 секунд; после него бот переключается на обычный поиск. Платный API и облачный ключ для модели не нужны.

## Демонстрация за несколько минут

1. `/start`, затем `31.04`: бот попросит исправить дату.
2. `26.06`: появится профиль Рака и меню. По дню найдутся пять человек, поэтому можно показать две страницы и сообщение об окончании базы.
3. «Знаменитости этого знака»: отдельная подборка со своим счётчиком страниц.
4. Напиши «музыканты моего знака», затем «актёры в июне» и «Влад А4».
5. Нажми «Угадай знак», ответь на несколько вопросов, открой статистику.
6. «Моя карточка» создаёт сообщение с картинкой; кнопка «Поделиться» открывает выбор чата в Telegram.
7. Перезапусти бота и отправь `/start`: дата и счёт сохранятся. `/forget` удалит их.

`/start` начинает подборки заново, сохраняя дату. Ввод новой корректной даты меняет профиль и сбрасывает подборки. Старые кнопки перестают действовать. Повторное нажатие использованной кнопки продолжения не дублирует людей. Один человек может появиться в подборке по дню и по знаку: это разные списки. Последняя страница содержит от одного до трёх человек.

## Устройство проекта

- `bot.py` — конфигурация, зависимости, команды и запуск.
- `handlers.py` — сообщения, отдельные хэндлеры подборок, поиск и викторина.
- `keyboards.py` — inline-кнопки и callback-данные.
- `zodiac.py` — проверка даты, знаки и краткие характеристики.
- `celebrities.py` — загрузка каталога, фильтрация, пагинация и оформление.
- `assistant.py` — клиент Ollama, проверка ответа модели и резервный поиск.
- `experience.py` — профиль, отсчёт дней, карточка и вопросы викторины.
- `storage.py` — SQLite: дата и счёт пользователя.
- `data/celebrities.json` — каталог со ссылкой на источник у каждого человека.
- `data/README.md` — происхождение данных и правила расширения.
- `scripts/setup_bot.py` — установка аватарки и описания бота через Telegram API.
- `tests/` — проверки логики и сценариев через диспетчер aiogram.

SQLite хранит Telegram ID, день, месяц и счёт в `data/profiles.sqlite`. Год рождения и история вопросов не сохраняются. Временные состояния и номера страниц находятся в памяти: после перезапуска подборки начинаются сначала. `SimpleEventIsolation` обрабатывает быстрые действия одного пользователя последовательно. Смещение страницы увеличивается после успешной отправки.

Каждая кнопка содержит идентификатор сессии, а кнопка продолжения — ещё и смещение. Это защищает от старых кнопок и повторной отправки страницы. У вопросов викторины есть отдельный идентификатор раунда: повторное нажатие не добавляет баллы.

Для проверки даты используется високосный 2000 год, чтобы принять `29.02`. Отсчёт для этой даты идёт до следующего 29 февраля. День определяется по московскому времени. Зодиакальные границы фиксированные; характеристики написаны для развлечения.

## Данные и расширение

Даты сверены с открытыми биографическими данными [Wikidata](https://www.wikidata.org/) и Wikipedia; ссылка на конкретную запись хранится в поле `source`. Описания короткие и составлены для проекта. Источники могут содержать ошибки, поэтому сомнительные записи стоит проверять вручную.

Чтобы добавить человека, допиши объект в `data/celebrities.json`. Нужны уникальный `id`, `first_name`, `last_name`, `day`, `month`, `zodiac`, `description`, `category`, `aliases` и `source`. У новых записей `birthday_source` дополнительно указывает календарный список с датой. `nickname` необязателен. Категории: `blog`, `music`, `screen`, `sport`. Псевдонимы на русском и английском удобно включать в `aliases`.

После изменения JSON перезапусти бот. Пакетный импорт уже выполнен: загрузчики и исходные списки кандидатов для запуска не нужны. Подробнее об источниках — в [описании каталога](data/README.md).

## Проверки

```bash
python -m pip install -r requirements-dev.txt
python -m unittest discover -s tests -v
python -m ruff check .
python -m ruff format --check .
```

Проверяются наличие минимум четырёх человек на каждой из 366 дат, уникальность записей, границы знаков, независимость пользователей и подборок, старые кнопки, повторные нажатия, сохранение профилей, викторина, поиск и отказ модели. Для тестов не нужны настоящий токен и запущенная Ollama: обращения к Telegram и генерация ответов модели подменяются.

## Передача проекта и GitHub

Передавай всю папку проекта или ZIP-архив: одному `bot.py` нужны остальные модули, каталог и картинки. Для публикации подготовлена чистая копия без `.env`, `.venv`, пользовательской SQLite-базы, кэшей и логов. В ней есть `.env.example` с пустым шаблоном токена и `.gitignore`. Каждый участник создаёт свой локальный `.env` по инструкции установки.

Автоматических CI-процессов в проекте нет. Проверки из `tests/` запускаются вручную.
